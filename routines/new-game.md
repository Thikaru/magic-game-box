# ルーチン①: 本日のゲームを新規作成

- 名前: `本日のゲーム作成`
- トリガー: Schedule — 毎日 6:00(タイムゾーンは Asia/Tokyo になっているか確認)
- リポジトリ: このリポジトリ
- コネクタ: 不要(全部外してよい)

以下をルーチンのプロンプト欄にそのまま貼り付ける。

---

あなたはこのリポジトリの「本日のゲーム」を作成する担当です。
まず CLAUDE.md を読み、規約をすべて守ってください。

手順:

1. `date +%Y-%m-%d` で今日の日付(Asia/Tokyo)を確認する。TZ=Asia/Tokyo を付けること。
2. `games.json` を読む。今日の日付のゲームがすでに存在する場合は何もせず終了する。
3. `games.json` の**前日(直近1件)**のジャンルを確認し、同じジャンルにならない
   ものを選ぶ(直近7件全体との重複は気にしなくてよい)。既存のジャンル一覧から
   1つ選ぶだけで満足せず、**2つ以上のジャンルを掛け合わせた組み合わせ**
   (例:「パズル×レース」「カード×育成」「脱出×リズム」)や、**既存ジャンルの
   枠に収まらない新しい仕掛け・遊び方**を積極的に狙うこと。「こういうゲームが
   あったら面白いかも」という発想を優先し、無難などこかで見た構成に逃げない。
   `routines/games-log.md`(制作記録)を読み、既存作品とコンセプト・仕掛けが
   被っていないか確認し、ジャンル内でも毎回ひとひねり入れて過去作の焼き直しに
   しないこと。
4. `games/YYYY-MM-DD-<slug>/` フォルダを作成し、`index.html`(+必要なら `game.js`)と
   `meta.json` を実装する。CLAUDE.md の必須要件(説明画面から開始 / もういちどボタン /
   トップへ戻るリンク / 外部依存なし / タッチとキーボード両対応 / 音が核となる
   ジャンルなら Web Audio API での効果音・BGM)を必ず満たすこと。
   見本として `games/2026-07-07-block-breaker/` の構造を参考にしてよい。
5. 難易度は「初見で1〜3分遊べて、少し悔しくてもう1回押したくなる」程度に調整する。
   ただし単調な固定難易度にはせず、**時間経過・スコア・レベル/ラウンド進行の
   いずれかに応じて段階的に難しくなる**カーブを必ず組み込む(速度上昇、出現頻度
   増加、選択肢の複雑化など、ジャンルに合った手段でよい)。
   遊び方の説明が一目で伝わるよう、操作方法・勝利条件・注意点を説明画面に
   具体的に書くこと(「〜だけ」「たまに〜」のような曖昧な説明で終わらせない)。
6. **セルフレビューと修正**: 実装が一通り終わったら、一度実装者の視点を離れて
   コードを読み直し、以下を確認してその場で修正する。
   - 難易度カーブ: 序盤が簡単すぎないか/終盤まで単調でないか。手順5の
     基準を満たすまで数値(速度・出現間隔・敵の量など)を調整する。
   - バグ・詰み: 操作不能になる、判定がすり抜ける、無限ループ、スコアが
     おかしくなる等がないか。説明画面→プレイ→ゲームオーバー/クリア→
     もういちど、を最初から最後までコードレビューでトレースする。
   - 説明文の分かりやすさ: 初見のプレイヤーが「何をすればいいか」を
     読んだだけで理解できるか。
   問題が見つかった場合は修正し、直した内容が新たなバグを生んでいないか
   もう一度確認する。
7. `games.json` の先頭に新しいゲームを追加する。既存エントリは変更しない。
   合わせて `routines/games-log.md` にも1行(日付・ID・ジャンル・コンセプトの要約)を追記する。
8. 品質チェック:
   - `python3 -m json.tool games.json` が成功すること
   - `node --check` で JS の構文エラーがないこと
   - 開始→プレイ→終了→リトライの流れをコードレビューして論理的に確認すること
9. `claude/game-YYYY-MM-DD` ブランチにコミットし、
   PR タイトル `game: YYYY-MM-DD <ゲームタイトル>` で PR を作成する。
   PR 本文にはゲームの概要・操作方法・工夫した点を書く。

成功条件: 新しいゲームフォルダ・games.json・routines/games-log.md の更新だけを
含む PR が1つ作成されていること。それ以外(index.html / archive.html / assets /
過去のゲーム / CLAUDE.md)は一切変更しないこと。
